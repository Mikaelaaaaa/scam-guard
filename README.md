# scam-guard

台灣中文詐騙訊息偵測。

輸入是一則、或一串轉傳的訊息；輸出是詐騙可能性、信心值、詐騙類型、逐條依據與
建議動作。判定由 33 個規則檢查產生，每一條依據都可以回指到訊息裡的某一個句子。

## Demo

```bash
pip install -e ".[dev,demo]"
python app.py
```

介面有兩個模式：

- **詐騙對練** —— 你扮演詐騙方打字，受害方由系統回應，而受害方說的每一句都是
  判定結果的對話化呈現。它只會說判定裡有的東西。
- **這是詐騙嗎** —— 貼上你真的收到的訊息，輸出是判定、依據與建議動作。
  多則轉傳以**空行**分隔。

`app.py` 是介面層的唯一檔案。位置不是自由選擇：`pyproject.toml` 的 `banned-api`
對 `gradio` 的訊息已經指名它，`per-file-ignores` 也已經豁免它，而 HuggingFace
Spaces 固定執行 repo 根目錄的 `app.py`。

## 系統架構

### 一次 `detect()` 的資料流

`scam_guard.pipeline.detect()` 是系統唯一的偵測入口。它不接受全域設定：
registry、權重表與上限全部由呼叫端傳入，因為消融實驗需要同時跑兩組不同設定。


`tools/` 與 `net/` 的差別不是「都會上網所以是同一件事」，而是**什麼時候上網**：
`tools/` 在部署前由人執行一次，失敗是人看得到的；`net/` 在每一次請求的路徑上，
失敗必須被檢查自己吞掉並轉成「沒有訊號」。

外部格式的知識只住在 `tools/`。`scam_guard/blocklist.py` 只認識一個我們自己
定義的格式（`entries.jsonl` 加 `manifest.json`），data.gov.tw 的下載網址、中文
欄位名稱、UTF-8 BOM、民國紀年全部不在核心裡。理由不是乾淨，是**資料集改版時會
壞在哪裡**：若核心知道欄位叫什麼，改版會在一個線上請求裡拋 `KeyError`，而
`Check` 協定要求檢查自行捕捉例外回傳空陣列 —— 於是黑名單會安靜地變成空的。
一個看起來正常運作、但硬證據永遠不命中的系統，是最怕的失敗模式。

## 設計原則

### 能用規則判的不叫 LLM

33 個檢查全部是規則。`Stage.LOCAL` 的 32 個在毫秒內跑完、零對外連線、每一次
命中都附一個可回指到原文座標的 `detail`；規則不會幻覺，因為它不生成任何字。
唯一昂貴的那一層被短路規則擋在後面：硬證據命中時根本不執行它。

這不只是偏好。執行環境是 HuggingFace Spaces 免費層（2 vCPU / 16 GB，無 GPU），
而 Gradio 與模型在**同一個程序**裡。Gemma 3 1B 而非 4B，是因為 4B 在 2 vCPU 上
約 2–5 tok/s，而本層輸出是 100–200 token 的結構化 JSON —— 單次判讀 40 秒起跳。
在這個機器上，「先跑規則」與「先跑模型」差的不是幾個百分點，是能不能用。

### 輸出是機率與信心兩個獨立的量

```
詐騙可能性  0.87        信心不足時為 None，呼叫端顯示「無法判定」
信心值      0.90        這一則判定有沒有足夠依據，不是準確率
```

分數 0.5 有兩種完全不同的來源：訊號互相矛盾，與完全沒有訊號。兩者都沒有依據
下判斷，所以兩者信心都低。信心低於 `confidence_floor`（0.40）時
`scam_probability` 是 `None` 而不是一個數字 —— 用型別強制呼叫端處理這個情況，
而不是把「不要顯示 0.5」這條規則散佈到每一個 client。`confidence` 一律填實際
值，讓呼叫端看得到系統為什麼閉嘴。

**不使用紅黃綠三級。** 三個顏色壓不出兩個獨立的量：「可能性 0.9、信心 0.9」與
「可能性 0.9、信心 0.2」在任何三級制裡都是同一個紅色，而它們是完全不同的兩件事。

這條以**簽章**守住：`compute_confidence()` 不接收 `Score`。「分數高所以信心高」
在直覺上成立、在語意上完全錯誤 —— 一則命中五條 Tier-B 的防詐宣導文分數很高，
依據卻很弱。拿不到的東西不會被誤用。

### 依據是組裝出來的，不是生成出來的

```
依據行 = detail  [+ 一段取自 doc.raw_at(coord) 的原文片段]
```

可測形式：對每一行依據，去掉原文片段之後 MUST 等於某個 `hit=True` 結果的
`detail`。這條規則的價值不在文風，在於它**從結構上排除了一整類錯誤**：一個會
自己寫句子的呈現層可以寫出「此網域註冊於 6 天前，屬高風險」—— 前半來自
`detail`，後半是它自己加的判斷，而沒有任何地方會報告它。

禁的是宣告與推測，不是用字。「可疑」「危險」「很可能」被擋掉，因為它們要求
使用者相信我們；「這個網域 6 天前才註冊」給了使用者他自己能判斷的東西。而
「evil.com 於 2026-08 列入 165 反詐騙諮詢專線_遭停止解析涉詐網站」含「詐」字，
它是一個可查證的引用，是依據的範本而不是反例。

### 誤判率是強制驗收指標

不是「盡量少誤判」，是誤判率決定門檻怎麼設，而且方向是刻意的。

具體的例子：`confidence` 的第三級（恰好命中一個群組）是 0.35，**刻意低於**門檻
0.40。後果是只命中一條 Tier-B 的訊息一律拒答，棄權率因此提高。選這個方向的
理由是「高薪日結免經驗」「保證獲利」這類句子在合法的打工與理財廣告裡大量出現。

同一個判斷出現在計分層：分數下限為 0，系統不產生「這不是詐騙」的宣稱。合法
訊息的特徵是**沒有**詐騙特徵，那是證據不存在，不是反向證據存在。代價講明白 ——
`p` 的值域因此是 `[0.5, 1)`，系統永遠不輸出低於 0.5 的可能性。

### 禁止臆測性 fallback

查不到就是查不到，不可以退成一個數字。

- `domain_age` 的三種查詢結果（查到、查到但沒有建立日期、問不到）在**型別上
  分開**，MUST NOT 互相代替。最誘人的 fallback 是「查不到就當作沒有訊號」，
  它危險的原因是「查不到年齡」與「網域很老」會產生同一個輸出：兩者都是空陣列。
  於是一則帶著全新釣魚網域、但 RDAP 剛好逾時的訊息，與一則帶著十年老網域的
  訊息，在下游看起來一模一樣。
- 計分層遇到未登錄於權重表的訊號讓 `KeyError` 傳播，MUST NOT 以 0 權重略過 ——
  一個沒有權重的訊號悄悄不計分，等於少一個證據而沒有任何地方會說。
- 呈現層遇到越界座標讓 `KeyError` 傳播，MUST NOT 吞掉 —— 吞掉的話，一個算錯
  座標的檢查會變成少一行依據，而少一行不會有人發現。
- 權重表在**組裝階段**就驗證 registry：註冊了一個未登錄於表中的檢查時當場拋
  例外，而不是延後到第一次查表。延後的話，一個沒人命中的新規則可以在表外活很久。

## 現況與限制

這一節是專題報告的一部分，寫的是目前量到什麼、還缺什麼，不是路線圖。

**規則層對真實語料的召回率很低。** 開發樣本取自 Cofacts，1,200 則
（600 則社群查核為詐騙的正例 + 600 則政策宣導與商業廣告的難負例）；對其中的
正例，只有約 0.4% 產生硬證據命中。規則寫的是「合法機構不可能送出的言語行為」，而
真實流傳的詐騙訊息大量是一頁式購物廣告、投資群組邀請、無話術的純連結 ——
規則層對它們**結構上**就不該命中。這正是 LLM 層要補的洞，也是為什麼系統的
主要輸出之一是「無法判定」而不是一個勉強的數字。正式的混淆矩陣與召回率屬
`add-metrics`，尚未落地。

**「跑了但問不到」說得出來了，但還沒有人聽。** `add-indeterminate-outcome`
已合併：`CheckResult` 多了 `indeterminate` 這個正交的第二軸（`hit` 答「有沒有
訊號」、`indeterminate` 答「這筆結果能不能信」，`hit=True` 且
`indeterminate=True` 不合法），`domain_age` 的 `NO_DATA` 與 `UNAVAILABLE`
因此各產出一筆 `hit=False, indeterminate=True` 的結果，不再與「查到了，網域
五年老」同形。**但 `confidence.py` 目前還沒有讀它** —— `cap_indeterminate`
屬後續的 scoring PR。所以後果的方向沒有變：RDAP 失敗時信心值仍然**偏高**，
系統在它其實不知道的時候輸出一個看起來很有把握的信心值。現在少的不是表達
能力，是消費者。

**`.tw` 網域拿不到註冊日期。** TWNIC 的端點是 `https://ccrdap.twnic.tw/tw/`，
而且它**確實提供** `registration` 事件（以 HTTP/2 查 `esunbank.com.tw` 得到
`1997-05-01T03:57:36Z`）。問題在協定版本：TWNIC 對 HTTP/1.1 回
`426 Upgrade Required`，而 `net/` 只用標準庫，`urllib` 不支援 HTTP/2。後果直說：
在不引入 HTTP/2 客戶端的前提下，這個訊號在 `.tw` 上是空的 —— 而 `.tw` 正是台灣
詐騙網域最相關的那一個。

**誤判率門檻還無法驗證。** 目標是誤判率的 Wilson 95% 上界 ≤ 2%。零誤判時
Wilson 上界化簡為 `z² / (n + z²)`，是一個只依賴 n 的量：`n = 149` 給的是
**2.51%**，要 ≤ 2% 需要 **189 則** hard negative。專案早期文件四處寫的「149 則」
是 rule of three（`3/149 = 2.01%`）的數字，不是 Wilson 的，`add-metrics` 已記錄
這個不一致。目前這批人工標註的 hard negative 還不存在，所以這個指標尚未被量過。

**全部權重與門檻都是佔位值。** `weights.toml` 的 60 處 `basis` 全部是
`"placeholder"`，`blocked_on = "add-testset"`。因此機率只保證**單調**（證據愈強、
愈多群組命中，`p` 愈大），不保證校準 —— 在 `add-metrics` 產出校準曲線之前，
輸出 MUST NOT 被描述為校準過的。

**LLM 層尚未落地。** `add-llm-client` / `add-llm-prompt` / `add-llm-schema` /
`add-llm-validate` 都還在 `openspec/changes/`，程式碼裡沒有任何模型呼叫。目前
`Stage.EXPENSIVE` 只有 `domain_age` 一個檢查，短路規則的另一半還沒有消費者。

**類型涵蓋 165 的 67.6%，不是全部。** `ScamType` 有 18 個成員，對應 165 打詐
儀錶板 191,912 筆案件中的 20 個 `CaseTitle`，合計 129,753 件（67.6%）。明確排除
5 個類別（網路購物、假廣告、信用卡遭盜刷、假預付型消費、其他，合計 57,387 件、
29.9%），理由是它們的判定要件不在訊息裡 —— 一則「您的訂單有誤」單看訊息無法
分辨是詐騙還是真的訂單有誤。另有約 29% 的案件（假投資、假交友）前期訊息全部
無害，需要長期軌跡追蹤，不是單則判定解得開的。兩組類別互不重疊。

**規模。** 程式碼 9,792 行（`scam_guard/` + `net/` + `tools/` + `app.py`），
測試 9,247 行、37 個檔案，全部不需要網路。`weights.toml` 登記 51 個條目
（33 個訊號 + 18 個類型）。
## REST API

```bash
pip install -e ".[dev,api]"
uvicorn api.app:app --host 127.0.0.1 --port 8000
```

兩個端點：`POST /check` 與 `GET /health`，欄位說明在 `/docs`。

```bash
curl -s localhost:8000/check -H 'content-type: application/json' \
  -d '{"messages":[{"text":"您好，我是警察...","from":"them","at":"2026-09-14T10:00:00Z"}]}'
```

`POST /check` **一律回 200，包含拒答** —— 拒答是系統正確地判斷自己沒有足夠
依據，那是一次成功的推論不是一次失敗。請讀 `abstained` 這個布林欄位，
**不要對 `scam_probability` 做數值比較**：它在拒答時是 `null`，而
`null > 0.5` 在 JavaScript 裡靜靜地是 `false`，於是「系統沒把握」會被讀成
「不是詐騙」。

`evidence` 的每一行**可能含請求中訊息的原文片段**（規則層的依據多半以一段引自
原文的句子作為可查證性的來源）。本服務不記錄它，呼叫端也不應該記錄。

回應不含證據座標、不含逐項檢查記錄、不含可記錄投影。座標不送的理由不是隱私，
是送了也解不對：解析座標需要 `Document`，而它在請求結束時就消失了。

### 部署層要求

**本服務 MUST NOT 在沒有網路層存取控制的情況下直接公開暴露。**

它不做認證、不做速率限制、也不做 API 版本協商，三者都是刻意的：在應用層發明
一套 token 格式是在為一個還沒有需求的東西寫程式碼。但風險是真的 ——
一個無認證的公開端點是一個免費的「這則訊息是不是詐騙」神諭，詐騙方可以拿它
逐句調整話術直到分數掉下門檻。所以這一條記為**部署層**的要求（反向代理的
存取控制、內網、或 mTLS），而不是假裝應用層擋住了。

`GET /health` 的 `weights.path` 會揭露伺服器上的絕對路徑，前提也是同一條。

### 未預期例外的回應形狀不一樣

`POST /check` 的錯誤回應是 `{"error": {"code", "field", "message"}}`，
但**未預期例外（500）不是這個形狀** —— 那條路徑交給 ASGI 框架的預設行為，
回一個不含 traceback 的純文字 500。本專案禁止 `except Exception`，
而 `@app.exception_handler(Exception)` 在效果上就是它。

呼叫端因此必須把「非 2xx 且非 `ErrorResponse` 形狀」當成一個獨立的失敗分支，
不能假設全部錯誤都解析得出來。這條路徑理論上不該被觸發：觸發即代表
`Check.__call__` 的協定（「依賴外部服務的檢查 MUST 自行捕捉例外」）被破壞了。

## 這個系統會不會把你的訊息送出去

**預設不會。** 訊息的正規化、切句、規則比對、165 涉詐網址黑名單比對、
TLD 風險、品牌相似度全部在本機完成，用的是預先下載好的本機快照。

**唯一的例外是網域年齡檢查（`domain_age`），而它預設不啟用。**
啟用它需要組裝層顯式注入一個查詢器（`net.rdap.RdapLookup`）；
不注入時系統照常運作，只是少一個訊號。

啟用之後會發生的事，逐項列舉：

- 訊息中每個連結的**可註冊網域**（例如 `https://login-esunbank.evil.com/a?token=abc`
  只取 `evil.com`）會被送到**該網域的註冊局**，查詢它的註冊日期。
- **不送**完整網址、路徑、query 參數、主機的子網域、訊息內容，
  也不送任何可識別你的資訊。
- 已知短網址服務的網域（`reurl.cc`、`bit.ly` 等）**不查詢**。
- 黑名單已命中時**不查詢** —— 最可疑的那批網域反而不會外流。
- 查過的網域會存進本機的 SQLite 快取（預設 `data/rdap/cache.sqlite3`），
  7 天內不重複查。清除用 `python -m tools.prune_rdap_cache`。

註冊局（以及網路路徑上的觀察者）因此會知道「某個 IP 在某個時間查了這個網域」。
它學不到是誰收到訊息、訊息內容是什麼、系統最後判成什麼。這比展開短網址
少非常多，但它不是零 —— 所以這個檢查預設關閉，開啟它是一個要顯式做的決定。

個資遮蔽的位置也是同一個推論的產物：遮蔽只在**寫入 log 之前**套用，不在呼叫
模型之前。推論與介面同程序，未遮蔽的原文與模型在同一塊記憶體裡，對模型遮蔽
保護不了任何東西；而 log 長期保存、事後可能被人翻閱，那才是真正的外流面。
`Verdict.redacted` 是取得可記錄投影的唯一途徑，HTTP 回應與 UI MUST NOT 顯示它。

## 開發

```bash
python3 -m pytest -q        # 全部測試，不需要網路
python3 -m ruff check .     # lint，含架構界線（scam_guard/ 不得 import 網路函式庫）
```

`tests/test_gradio_demo.py` 以 `pytest.importorskip("gradio")` 開頭，本機沒裝
`[demo]` extra 時整個檔案會被跳過。CI 因此安裝 `.[dev,demo]` —— skipped 不會讓
CI 變紅，安靜跳過的測試等於沒有測試。

部署前需要的本機快照：

```bash
python -m tools.fetch_psl                # Public Suffix List
python -m tools.fetch_blocklist          # 165 涉詐網址黑名單
python -m tools.fetch_rdap_bootstrap     # IANA RDAP 端點對照（僅啟用 domain_age 時需要）
```
